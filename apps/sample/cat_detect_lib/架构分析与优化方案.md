### 目录现状

## 🔍 存在的问题

### 1. 文件组织混乱
- 所有文件混在根目录
- 头文件和源文件没有分离
- 核心功能和辅助功能混杂

### 2. 命名不清晰
- 部分文件命名不够直观
- 难以快速识别文件功能

### 3. 架构不清晰
- 模块边界不明确
- 依赖关系不清晰

## 📦 模块划分说明

### 1. include/ - 头文件目录
统一管理所有头文件，按功能分类。

### 2. include/api/ - 对外API
存放对外暴露的接口头文件，是库的公共接口层。

### 3. include/core/ - 核心功能头文件
存放核心检测算法相关的头文件。

### 4. include/utils/ - 工具类头文件
存放各种工具函数的头文件。

### 5. src/ - 源文件目录
所有实现文件放在这里，按功能模块分类。

### 6. src/core/ - 核心检测算法
- **猫检测**: lib_video_alg_catdetect.c
- **人体检测**: lib_ts_alg_body_detect.cpp
- **算法库**: lib_tsalg_alg_lib.c, lib_tsalg_alg_rsn.c
- **食物检测**: lib_food_rsn.c

### 7. src/utils/ - 工具类实现
- **YUV处理**: qi_nv12_yuv.cpp
- **行为检测**: lib_act.c
- **数组差异**: lib_array_diff.c
- **文件同步**: lib_file_sync.c, lib_dirsync.c
- **网络通信**: lib_iot_net.c

### 8. src/record_file/ - 录像相关
录像文件处理功能。

### 9. config/ - 配置文件
存放OTA等配置文件。

## ✨ 优化优势

### 1. 可读性提升
- 清晰的目录结构，一眼就能找到所需文件
- 按功能分类，便于理解代码组织

### 2. 可维护性提升
- 模块边界清晰，修改一个模块不影响其他模块
- 头文件和源文件分离，便于管理

### 3. 可扩展性提升
- 新增功能可以按模块添加到对应目录
- 架构清晰，便于理解和扩展

### 4. 代码质量提升
- 强制按模块组织，减少耦合
- 便于代码审查和测试

修改 CMakeLists.txt 或 Makefile，使用新的目录结构。

## 🔧 CMakeLists.txt 示例

```cmake
cmake_minimum_required(VERSION 3.10)
project(cat_detect_lib)

# 设置源文件
set(SOURCES
    src/core/lib_video_alg_catdetect.c
    src/core/lib_ts_alg_body_detect.cpp
    src/core/lib_tsalg_alg_lib.c
    src/core/lib_tsalg_alg_rsn.c
    src/core/lib_food_rsn.c
    src/utils/qi_nv12_yuv.cpp
    src/utils/lib_act.c
    src/utils/lib_array_diff.c
    src/utils/lib_file_sync.c
    src/utils/lib_dirsync.c
    src/utils/lib_iot_net.c
    src/record_file/ts_rne_record_file.c
)

# 设置头文件目录
include_directories(
    include
    include/api
    include/core
    include/utils
)

# 生成库
add_library(cat_detect_lib STATIC ${SOURCES})
```
